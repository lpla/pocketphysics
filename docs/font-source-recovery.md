# Historical Font Creation Source Recovery

## Result

The complete 2,680-byte uLibrary text executable unit, including the
808-byte `ulCreateFont` method, now compiles entirely from C. The font's ARM9
post-link replacement is removed. No C function body, instruction encoding,
literal value, or relocation is rewritten to obtain the match.

The preserved [text.c](../research/reconstruction/v06/dependencies/ulibrary/base/text.c)
has SHA-256
`1ec6080d86b55e97f5dee2fe65eea62d10ed0795a1d2dc8d81a7b77ecc675584`.
An ordinary whole-file compile produces six commuted address operands in
`ulCreateFont`. Compiling its unchanged C body separately produces the
released operands. This constrains a reproducible compilation context; it
does not establish the original producer's source-file partition.

## Compilation Context

The [partition helper](../tools/repro/prepare_ulibrary_text.py) checks the
preserved source identity, extracts the complete font function between unique
named boundaries, and emits two C compilation units. Every original C body
and data declaration is preserved byte for byte. The font unit adds only
the existing header include and an external helper prototype.

Both units use the historical devkitARM r21 GCC 4.1.2 `-O2` recipe. The core
unit also uses `-ffunction-sections`. The
[relocatable layout](../research/reconstruction/v06/dependencies/ulibrary/text-object-layout.ld)
restores all ten complete functions and constant data to the released order.
This performs ordinary linker relocation of source-produced code and data;
it contains no recovered instructions or opaque payloads.

The resulting `text.o` has 4,804 allocated bytes: 2,680 executable bytes,
2,064 constant-data bytes, 12 string bytes, 40 initialized-data bytes, and
eight zero-initialized bytes. Its
[normalized identity](../research/reconstruction/v06/dependencies/ulibrary/text-object-identity.json)
is `4b5eb0cdaba793fdc72623fa43a6de5876aab33e02efe71ff682fefc130164fd`.

## Acceptance and Limits

The [unit tests](../tools/repro/test_prepare_ulibrary_text.py) check lossless
source partitioning, exact generated bytes, changed-source rejection before
writing, duplicate/missing boundaries, and reversed boundaries. Complete
object identity covers flags, allocated layout/data, relocations and exports.
The entire unmasked ARM9 link must match the guarded hash before the remaining
unrelated replacements are applied; final processor and ROM identities are
independent gates. Two clean builds compare all outputs and provenance.

```sh
tools/repro/test_source_patches.sh
tools/repro/test_v06_exact.sh
```

This recovery is not a performance change or proof of arbitrary-font behavior.
Historical behavior remains preserved byte for byte. The
[remaining inventory](executable-source-coverage.md) distinguishes unresolved
high-level reconstruction from exact binary reproduction.
